### 2026-11-24 ｜ Day 02 ｜ 涉及编号：T02

- **现象**：`create_five_dtypes()` 五个变量里四个写成浮点字面量 `torch.tensor([1., 2., 3.])`，
  只有靠 `dtype=` 才凑齐 5 种。其中 `t_f32` 和 `t_i64` **两个"碰巧对"**——
  因为默认推断恰好就是 `float32` 和 `int64`，删掉 `dtype=` 也能过。
- **错误分类**：**K**（知识混淆）——把"字面量的长相"当成"我要的 dtype"
- **根因**：PyTorch 的默认推断规则是**看小数点**：有 `.` → `float32`，无 → `int64`，
  `[True]` → `bool`。规则本身没错，错在**依赖默认值**：默认值今天等于期望值，
  明天换成 `float64` 就 silently 变成 `float32`，而 assert 之外的代码不会察觉。
- **对策**：① 五个全部显式写 `dtype=`；② 值也写成一致的样子——整数 dtype 配 `[1, 2, 3]`
  而不是 `[1., 2., 3.]`（实测 `int32([1.7, 2.9])` → `[1, 2]`，**静默截断不报错**）；
  ③ 立判据：**"碰巧通过"和"写对了"在输出上长得一模一样**，只能靠"删掉这行会不会崩"来区分。
- **是否复现验证**：是——实测 `torch.tensor([1.,2.,3.])` → float32、
  `torch.tensor([1,2,3])` → int64、`torch.tensor([True])` → bool、`torch.zeros(2,3)` → float32

### 2026-11-24 ｜ Day 02 ｜ 涉及编号：T02

- **现象**：`calculate_image_memory_footprint()` 第一版写成
  `num_elements * torch.uint8.element_size()`，报
  `AttributeError: 'torch.dtype' object has no attribute 'element_size'`。
  改成问张量之后又写 `num_elements * element_size * 4`——**两处都多乘了一个 4**，
  但 `assert float32_bytes == uint8_bytes * 4` **照样通过**，输出还打印 `ratio=4.0x`。
- **错误分类**：**A**（不会应用）——记住了 `element_size` 这个名字，没记住它的单位已经是字节
- **根因**：`element_size()` 是 **Tensor 的方法**，返回"每个元素几字节"（uint8→1，float32→4）；
  `torch.uint8` 是 **dtype 对象**，只描述字节该怎么解释，自己没有尺寸。
  所以 `num_elements * element_size` **本身已是字节数**，再乘 4 是把单位算了两遍。
  **更值得记的是断言为什么没拦住**：两个数都大了 4 倍，比值仍是 4，
  而这条断言只校验**相对关系**，不校验**绝对量级**——它是个空洞断言。
- **后果**（若不修）：数值 4 倍偏差直接进 Day 15/24 的显存估算，
  8GB 能装多少帧会在"2000 帧"和"500 帧"之间错一个量级，而所有断言都是绿的。
- **对策**：① 量尺寸要问张量，不问 dtype；② 断言加**绝对基准**——
  已知 `64×3×84×84=1,354,752` 个元素，uint8 就该等于这个数，不写"是它的 4 倍"；
  ③ 立判据：**只校验比例关系的断言，必须再配一条钉住量级的断言**。
- **是否复现验证**：是——`num_elements*1*4` 与 `num_elements*4*4` 的比值仍为 4，
  原断言返回 `True`；修正后 `uint8=1354752`（= 乘积）、`float32=5419008`（= 4 倍）
- **与 Day 1 的关系**：这是「自洽 ≠ 正确」的第二个变体。Day 1 是**写入与校验共用同一个常量**，
  今天是**校验只覆盖了一半的维度**（比值对、量级错）。同一个病的两种长相。

### 2026-11-24 ｜ Day 02 ｜ 涉及编号：B01

- **现象**：`demonstrate_numpy_memory_sharing()` 里零拷贝演示本身写对了
  （`from_numpy` → `clone` → 改 numpy → 改 tensor），但后面多写了三行
  `shared_tensor[0]=10.0 / [1]=20.0 / [2]=30.0`，把刚改出的 999 和 888 **改回原值**，
  于是紧跟其后的两条断言必然失败。
- **错误分类**：**A**（不会应用）——知道零拷贝是什么，没意识到"断言读的是当前状态"
- **根因**：把"演示完把数据恢复干净"的直觉，放在了断言**之前**。
  这个函数的**产物就是改动后的状态**，恢复等于销毁证据。
  零拷贝只能靠"改一边、另一边跟着变"来证明，光比 `data_ptr` 是间接证据。
- **对策**：① 顺序固定为 `from_numpy → clone → 改 numpy → 改 tensor → 断言`，
  **断言永远在最后**；② 如果确实要恢复，只能写在断言**之后**（本函数不需要）；
  ③ 认清 `with h5py.File(...)` 里 `[0]` 取出的数组已被读进内存，
  `from_numpy` 共享的是这块内存，**文件关掉不影响张量**——Step 6 就是这么写的。
- **是否复现验证**：是——删掉三行重置后 `shared_tensor[0]=999`、`np_arr[1]=888` 两条断言通过，
  `cloned_tensor[0]` 仍是 `10.0`（clone 确实独立）

### 2026-11-25 ｜ Day 03 ｜ 涉及编号：T04

- **现象**：随堂快测问 `t = torch.zeros(84, 84, 3, dtype=torch.uint8)` 的 `stride()`，
  答成 `(84, 84, 3)`——把 shape 抄了一遍。追问 `p = t.permute(2, 0, 1)` 的 shape 与 stride，
  答「不知道」。**同一次快测的后两问（`view` 是否报错、`reshape` 是否报错）反而答对了。**
- **错误分类**：**C**（不懂概念）——知道「内存连续」这个词，但没建立 stride 的图像
- **根因**：stride 一直停留在名词层面。没有「沿某一维走一步，指针往前挪几格」这个画面，
  遇到提问只剩 shape 可用，于是用 shape 顶替。
- **对策**：用**放映厅座位号**类比——一整个厅没有过道，座位排成一条线，
  找「第 5 排第 3 座」靠 `5 × 每排座数 + 3`，那个「每排座数」就是 stride。
  推导规则：从最右维起算，`stride[i] = 右侧所有维 size 连乘`。
  ⚠️ **此规则只在连续时成立**，这条限定必须一起记（见下一条）
- **是否复现验证**：是——`t.stride() == (252, 3, 1)`；
  用偏移公式反查 `t[1][2]` → `1×3 + 2×1 = 5`，与展平后第 6 个元素一致

### 2026-11-25 ｜ Day 03 ｜ 涉及编号：T04

- **现象**：追问 `b = tensor([[0, 1, 2], [3, 4, 5]])`，问 `b.T` 的 stride，答 `(2, 1)`。
  那是 `b.reshape(3, 2)` 的答案；`b.T` 实际是 `(1, 3)`。
- **错误分类**：**C**（不懂概念）——上一条的第二次表现，仍在用「改形状 = 重排内存」推
- **根因**：**通式的前提没建立**。`stride[i] = 右侧 size 连乘` 描述的是连续张量的布局；
  `b.T` 不连续，它的 stride 是**跟着维度标签搬家**来的，不是重新算的。
  两条规则混成一条用，必然在这里翻车。
- **对策**：两条分开记——
  ① `permute` / `transpose` / `.T` 之后，stride 数字不变，只是位置跟着标签走（**无条件成立**）；
  ② `stride[i]` = 右侧 size 连乘（**只在 `is_contiguous()` 为真时成立**）。
  判连续不必背规则，直接对照：算一遍通式，和实际 stride 比。
- **是否复现验证**：是——`b.T.stride() == (1, 3)`；用 `b.T[0][1]` 反查偏移
  `0×1 + 1×3 = 3`，值是 3。若按 `(2, 1)` 会算出 offset 1、值 1，两者可区分。
  **当时给的提示 `b.T[2][1]` 是无效样本**——末元素在两种假设下都是 offset 5，验不出东西

### 2026-11-25 ｜ Day 03 ｜ 涉及编号：T04

- **现象**：判 `p.reshape(3, -1)` 的返回值，答「视图」。实际是**拷贝**
  （`p` 非连续，reshape 必须先 `contiguous()` 再 view）。
- **错误分类**：**K**（知识混淆）——把 `reshape` 当成 `view` 的别名
- **根因**：`reshape` 不是一个动作，是**一个分岔**：输入连续时等价 `view`，
  输入非连续时等价 `contiguous().view()`。默认它「什么都不干」，就会在 DataLoader
  里对每个 batch 反复触发隐藏拷贝，而没有任何报错提示。
- **对策**：三份契约分开记——
  `view` 保证**不拷贝**，做不到就 `RuntimeError`；
  `permute` 保证**轴序**，不保证连续；
  `reshape` 保证 **shape**，**不保证**是视图还是拷贝。
  判断结果不必猜，`x.reshape(...).data_ptr() == x.data_ptr()` 为 `True` 即视图
- **是否复现验证**：是——`p.reshape(3, -1).data_ptr() != p.data_ptr()`（拷贝）；
  另一处 `b.T.reshape(3, 2)` 因 shape 未变，返回视图，stride 仍是 `(1, 3)`
  ——**「reshape 之后一定连续」也是错的**

### 2026-11-25 ｜ Day 03 ｜ 涉及编号：T04

- **现象**：`b.shape()` 报 `TypeError: 'torch.Size' object is not callable`。
- **错误分类**：**A**（不会应用）——知道 `shape` 是什么，只是当成方法调了
- **根因**：PyTorch 的属性/方法形态**不统一**：`shape` / `dtype` / `device` / `ndim` / `T`
  是属性，`stride()` / `numel()` / `data_ptr()` / `is_contiguous()` 是方法。
  `stride()` 不接收参数却是方法，所以「要传参的才是方法」这条伪规律也不成立。
  另：**报错类型本身是线索**——`AttributeError` = 没有这个东西；
  `TypeError: ... is not callable` = 有，但不许这么用。
- **对策**：不确定就让 Python 回答——`type(b.shape)` 返回 `torch.Size`（属性），
  `type(b.stride)` 返回 `builtin_function_or_method`（方法）
- **是否复现验证**：是——`b.shape` 返回 `torch.Size([2, 3])`，可解包/索引/与元组比较，
  只是不能调用

### 2026-11-25 ｜ Day 03 ｜ 涉及编号：—（Python 异常 API）

- **现象**：`except RuntimeError as e: print(e.message)` 报
  `AttributeError: 'RuntimeError' object has no attribute 'message'`。
- **错误分类**：**A**（不会应用）——写法本身来自 Python 2
- **根因**：`.message` 是 Python 2 的遗留属性，Python 3 已移除，统一用 `str(e)`。
  这类写法在旧教程和老代码里极多，抄过来是一颗**哑弹**：只在异常真的发生时才炸，
  而那时你正在处理另一个错误，容易误判成「原来的 bug 变了」。
- **对策**：异常信息一律 `str(e)` 或 `print(e)`；要取首行用 `str(e).splitlines()[0]`
- **是否复现验证**：是——`hasattr(e, 'message')` 为 `False`；
  `str(e)` 首行为 `view size is not compatible with input tensor's size and stride...`

### 2026-11-25 ｜ Day 03 ｜ 涉及编号：T04

- **现象**：`except RuntimeError:` 分支里写 `print("view(3, -1) raised RuntimeError...")`，
  而 `view(3, -1)` **根本不抛**，这行永远不执行；改的那一版把 `raise ValueError` 的消息
  写成 `view(-1)`，触发条件却仍是 `view(3, -1)`。日志说 A，代码做 B。
- **错误分类**：**A**（不会应用）——验证证据是手写的，不是从对象里取的
- **根因**：把「我预期会发生什么」直接写成了「发生了什么」。日志因此失去证据价值，
  且比没有日志更糟：它会把排错方向带到错误的那一行。
- **对策**：**异常处理块里出现的每一句话，都必须来自 `str(e)`；断言里的每一个结论，
  都必须来自数据。** 模板：`except X as e: assert "<关键词>" in str(e), f"unexpected: {e}"`
  ——关键词对不上就当场失败，而不是把别人的错误冒充成你要的那条
- **是否复现验证**：是——改成 `view(-1)` 后捕获到真实消息
  `view size is not compatible with input tensor's size and stride (at least one dimension
  spans across two contiguous subspaces). Use .reshape(...) instead.`
- **与 Day 2 的关系**：Day 2 是「断言前把值改回去」，今天是「手写结论冒充证据」。
  同属一个病：**制造一个看起来正确的假象，让校验器失去意义**。

> 错误的预测至少会被执行结果当场打脸，而含糊的自信不会。
> 真正见效的对策是当天补上的**契约视角**：遇到任何 API，先说出它「保证什么、不保证什么」。
> 说不出来，就是该去 `print` 或读文档的时刻。
