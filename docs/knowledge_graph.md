## 二、四大枢纽

```
                    ┌─────────────────────────────────────────┐
                    │  PyTorch 的四个枢纽                       │
                    └─────────────────────────────────────────┘

   ①  Tensor  ──────────────┬──────────> ②  autograd 计算图
      （张量）               │              （自动微分）
      前置：Python/NumPy     │              前置：Tensor
      被依赖：一切            │              被依赖：参数更新、优化器
                             │
                             └──────────> ④  Dataset / DataLoader
                                            （数据接口）
                                            前置：Tensor
                                            被依赖：训练循环、本仓库的管道

   ③  nn.Module（模块化）
      前置：Tensor + autograd
      被依赖：模型定义、优化器、state_dict 保存加载

   汇流点：训练循环 = nn.Module + 优化器 + DataLoader
```

### ① Tensor（张量）— 第一枢纽

- **为什么是枢纽**：前置只有 Python/NumPy，但后面**每一个**概念都以它为输入输出。
- **三要素**：`dtype` / `shape` / `device`。任何 Tensor 报错，先查这三样。
- **它解释了什么**：图像为什么是 `uint8 [H,W,C]` 而模型要 `float32 [C,H,W]`；
  为什么 `.to('cuda')` 要显式调用。
- **在本仓库的位置**：Day 2-5 建立；Day 13 的视觉缝合是它的第一次实战。

### ② autograd（自动微分）— 第二枢纽

- **为什么是枢纽**：前置只有 Tensor，但"训练"这件事的全部魔法都在这里。
- **核心**：动态计算图、`requires_grad`、`backward()`、梯度累积。
- **它解释了什么**：为什么 `zero_grad()` 必须写；为什么 `torch.no_grad()` 能省显存；
  为什么 in-place 操作会让反向传播报错。
- **在本仓库的位置**：Day 6 建立。数据管道本身不训练，但 Day 9-10 的优化器理解依赖它。

### ③ nn.Module（模块化）— 第三枢纽

- **为什么是枢纽**：前置是 Tensor + autograd，被依赖面是"所有模型"。
- **核心**：参数容器 + `forward` 契约 + `state_dict` 序列化。
- **它解释了什么**：模型为什么能一行 `model.parameters()` 交给优化器；
  为什么保存模型存的是 `state_dict` 而不是整个对象。
- **在本仓库的位置**：Day 8-10。管道项目本身不定义大模型，但 Day 10 会用一个极小 MLP
  验证"数据 → 张量 → 训练"整条链路通了。

### ④ Dataset / DataLoader（数据接口）— 第四枢纽

- **为什么是枢纽**：前置只有 Tensor，但它是**本仓库的主角**——
  `source_brief.md` 的四周冲刺全部挂在这个枢纽下。
- **核心**：`__len__` / `__getitem__` 二元契约 + 批处理 + 多进程 + 预取。
- **它解释了什么**：为什么数据集不能一次装进内存；为什么多进程会死锁；
  为什么 `pin_memory=True` 能加速。
- **在本仓库的位置**：Day 11 建立契约，Day 12-27 全程深化。

## 三、依赖链方向（自左向右，箭头是"被依赖"）

```
Tensor ──> autograd ──> nn.Module ──┐
   │                                 ├──> 训练循环 ──> 模型训练
   └──────> Dataset/DataLoader ──────┘

Dataset/DataLoader ──> 具身数据管道（本仓库主线）
                          ├── 视觉张量缝合（Day 13）
                          ├── HDF5 懒加载（Day 15-16）
                          ├── fork 死锁与 worker_init_fn（Day 17-18）
                          ├── 状态规范化与动作分块（Day 22-24）
                          └── 吞吐量压测（Day 25-27）
```

**关键结论**：本仓库**跳过**③的主要篇幅，重点在①和④。
autograd 与 nn.Module 只学到"能验证链路通"的程度即可（Day 6、8-10），
Day 11 之后全部火力给④。

## 四、附属概念挂载表

### 附属 A — 操作手段（挂在①Tensor 下）

| 概念 | 编号 | 一句话 | 首现 |
|:---|:---|:---|:---|
| dtype 转换 | T02 | `uint8 → float32` 是图像进模型的必经路 | Day 2 |
| shape 手术 | T04 | `view`/`reshape` 改形状，`permute` 换轴序 | Day 3 |
| 索引与掩膜 | T05 | 从 `[N,7]` 里按条件取帧 | Day 4 |

| cat / stack | T08 | 把多帧拼成一个 batch 张量 | Day 20 |

### 附属 B — 桥（连接两个体系）

| 桥 | 编号 | 连接 | 首现 |
|:---|:---|:---|:---|
| `torch.from_numpy` / `.numpy()` | B01 | NumPy ↔ Tensor（**共享内存**，最易踩坑） | Day 2 |
| `cvtColor` | B02 | OpenCV BGR ↔ 模型要求的 RGB | Day 13 |
| `collate_fn` | B03 | Python 对象列表 ↔ 定形 batch 张量 | Day 11、20 |
| `worker_init_fn` | B04 | 主进程 ↔ 子进程的文件句柄隔离 | Day 18 |
| `pin_memory` | B05 | 可分页内存 ↔ 锁页内存 ↔ GPU | Day 25 |

### 附属 C — 时间序列层（挂在④Dataset 下）

|:---|:---|:---|:---|

## 五、复述检验（费曼检查）

1. 本模块的枢纽节点是什么？为什么它是枢纽（被依赖多 + 前置少）？
2. 它与其他枢纽的联系是什么（依赖链方向）？
3. 一个生活类比。

复述不流畅 / 说不清 = 该枢纽未吃透，回到地图与概念环节补强后再进入下一模块。
